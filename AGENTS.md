# UI work

- Before building a new page or screen, follow the ui-design-brief skill
- Follow ui-anti-slop on every UI task
- All colors, spacing, radius, and font sizes come from CSS variables defined once
- Use semantic HTML, visible focus states, and respect prefers-reduced-motion
- Never ship placeholder marketing copy, fake testimonials, or invented statistics
- Reply with what changed and what was assumed, in a few lines

# Engineering rules

- Follow the coding-style skill on all code
- For new projects or large features, follow project-planning before writing code
- Check git status and work on a branch before multi-file edits
- When something breaks, follow the debugging skill before changing code
- Run self-review before saying a task is done
- Never claim something works without running it
- Never hardcode secrets
- Create complete, runnable results instead of outlines
